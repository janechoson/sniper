# Risk policy

GMGN supplies discovery and normalized evidence. The cheap filter rejects invalid mints, stale strategy candidates, missing usable market data, zero liquidity, duplicates and confirmed critical security findings. Persisted processing state and a per-mint in-flight lock prevent concurrent pipelines and repeat analysis after restart.

Jev receives compact normalized facts and typed questions through the existing official TypeSafe System One integration, pinned to `jev-1.14.0`. It returns BUY/SKIP, LOW/MEDIUM/HIGH risk, suspicious and insufficient-data flags. It never signs, executes or receives a key. `knownBadFunding` has no decision role.

RiskEngine returns BUY, SKIP_RUG, SKIP_RISK, SKIP_JEV, SKIP_MARKET or SKIP_MISSING_CRITICAL_DATA with a human-readable reason. Critical rug/control/sellability findings win over Jev. Price/liquidity, mint/freeze control evidence, freshness, pinned Jev approval, concentration when actually known, available wallet funds and duplicate state are the small entry checks. Optional unknown holders/dev/social facts alone do not block. Normal live has no position-count gate; legacy maxPositions is discarded during settings normalization. Controlled sessions retain their independent one-BUY restriction.

Before each BUY, live execution reads current wallet SOL and atomically claims a pending principal reservation in SQLite alongside the intent and CREATED execution. Inside the same write transaction it checks spendable capital after the operational reserve and other pending BUYs, and requires the exact 1% integer amount. Execution remains serialized for the wallet. It checks fresh balances and exact sizing again before signing. Definitive unsigned failure releases the reservation; signed UNKNOWN retains it and blocks new BUYs until reconciliation. Insufficient spendable capital produces WAITING_FOR_CAPITAL / INSUFFICIENT_SPENDABLE_BALANCE and returns to WATCH for fresh approval, without a security finding or learning LOSS.

Normal BUY principal is exactly `max(balanceLamports − feeReserveLamports − pendingBuyLamports, 0) / 100n`. Fresh quotes, reverse route evidence, transaction inspection, simulation, wallet stability and on-chain mint decimals are checked before the final deterministic approval and signing. Unsafe execution is skipped rather than resized. The final ApprovedTradeIntent is bound to mint, side, amount, mode, snapshot and expiry.

Normal strategic exits are decided per position by Jev: HOLD, PARTIAL_SELL or FULL_SELL. The +30%/+70% TP and trailing parameters are context references only; they never force a normal automatic SELL. Price/PnL stop loss and maximum-holding-time exits are disabled, including legacy settings normalization. Negative PnL, age and position count alone are not exit reasons. Manual/emergency requests and current critical security/liquidity protection override Jev; every execution still requires transaction inspection, simulation, signing, confirmation and reconciliation. SELL backoff limits execution retries while market/PnL/MFE/MAE/Memory and asynchronous Jev analysis continue. The process must remain running. See [multi-position Jev exit engine](jev-exit-engine.md).

New-entry pause does not authorize duplicate trades or suppress protective exits. A durable signature is saved before execution broadcast. UNKNOWN keeps the pending reservation and pauses new entries; never blindly replay it. OPEN/CLOSED require actual confirmed receipt deltas and actual wallet balances. Legacy pending/open GMGN positions are preserved for review rather than silently adopted.

Smoke is a separate command. Per the owner's later explicit revision, its cap is **0.005 SOL / 5,000,000 lamports**. It cannot authorize normal 1% buys and requires its own ACK. It submits exactly one BUY and one SELL, selling only acquired tokens. A durable one-shot marker blocks replay; partial/unknown results require review.
