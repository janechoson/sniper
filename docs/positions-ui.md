# Positions card redesign

Implemented on the existing BOT B dashboard on 2026-10-28. The owner selected the current PaperDAO palette, so cards use the same cream surfaces, burgundy accent and shared semantic colors as Token Flow.

Only presentation files changed: `public/index.html`, `public/app.js`, `public/style.css`. No execution, ExitEngine, position states, persisted accounting, PnL/MFE/MAE calculations or backend endpoints were changed. The existing live process serves these static files directly; deployment does not require restarting the trading engine.

The page now has an active count, a compact portfolio summary and responsive cards. Cards have a token-initial avatar, copyable shortened mint with full-mint tooltip, semantic state badge, mode, prominent total PnL, original invested amount, latest available GMGN value, exact held quantity, entry/current price when supplied, position age, MFE/MAE and separate realized/unrealized results. Missing prices/excursions/valuation remain unavailable. Zero-quantity unreconciled BUYs display unknown holding/investment rather than claiming those placeholders are actual balances. If any active value is unavailable, aggregate current value and unrealized result display a dash.

Card total PnL preserves the previous formula: latest value minus remaining cost plus realized PnL, divided by original entry cost for the percentage. The summary's Invested is the remaining basis of current holdings; its unrealized percentage uses that same remaining basis. Tooltips distinguish these concepts. These are presentation aggregates of supplied integer lamports, not new accounting or reconstructed fills. Historical/stale GMGN valuations retain exact timestamps in tooltips and details, and exclude future SELL costs.

Attention cards sort before UNKNOWN, EXIT_PENDING, MONITORING_DEGRADED and OPEN. Warnings show the actual code, a human-readable rendering of its reason and retry countdown. Expanded details retain full mint/signatures, exact timestamps, remaining basis, raw reason/stage and exit status. No new error cause is inferred. Strategy chips show configured TP/trailing thresholds and neutral NO STOP LOSS; they do not claim trailing is currently activated.

Actions remain the existing confirmed `POST /api/exit` flow, with the same position ID and 50/100 percentage payload. Cancel sends nothing. Buttons disable while queued, selling or reconciling UNKNOWN. A manual retry on a token warning remains subject to all existing backend checks; this UI neither declares a route safe nor bypasses backoff/execution validation. History remains the existing separate CLOSED view. Mint copy and transaction explorer links are local/browser actions only.

Cards use a responsive grid, with a 650px maximum card width, and preserve expanded details across updates. Existing unchanged cards are retained between SSE refreshes; PnL changes have a brief highlight, new attention has one subtle warning pulse, and cards leaving the active list become inert before fading out. Reduced-motion preferences disable these effects. Relative age/retry text updates without triggering trading work.

Validation: lint, typecheck and build; isolated browser checks for 1/3/10/20 positions, multi-column layout, attention ordering, partial-position PnL, missing data, unknown unacquired balances, timestamps/details retention, confirmation/cancel and exact SELL payload, queued/UNKNOWN disabled actions, responsive widths 390–1920 and reduced motion. Prior dashboard/navigation/History/SSE/CSRF/flow checks remain included. All synthetic position/action fixtures run against the isolated paper UI server, never production.
