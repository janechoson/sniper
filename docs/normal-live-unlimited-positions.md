# Continuous normal live without position-count gates

Implemented on the current BOT B, 2026-10-28. No architecture replacement. Stop loss remains disabled.

1. **Gates found:** RiskEngine's `positions >= maxPositions`, Engine's pre-Jev capacity check, the controlled runtime settings override to one position, and the separately injected ControlledSession's one-BUY allowance.
2. **Normal live removal:** both count checks and the runtime maxPositions override are removed. Settings normalization discards the obsolete maxPositions key, including persisted legacy settings; it is removed from the checked-in strategy and Settings UI. Counts remain telemetry only.
3. **Controlled separation:** `pnpm live` launches `dist/live.js` and the normal server without a ControlledSession. Historical `controlledLiveRunV1` remains unchanged. `pnpm live:controlled` remains independently limited. Normal live has no one-trade completion shutdown.
4. **Risk:** every independent candidate still needs fresh GMGN/security, compatible SPL/Token-2022 policy, current Trading Memory context, pinned Jev approval, deterministic risk and fresh exact sizing. One or twenty OPEN positions have no bearing on approval. Operator entry controls remain enforced.
5. **Capital reservation:** SQLite BEGIN IMMEDIATE atomically checks current spendable funds and exact 1% against all current pending BUY reservations before inserting the intent/CREATED execution. Duplicate and signed unresolved checks occur at the same claim boundary. Definitive unsigned failures release capital; UNKNOWN retains it. No new standalone ledger was introduced.
6. **Fresh balance:** Engine context, Executor's pre-claim wallet read, pre-quote exact-sizing check and pre-signing final checks use integer lamports. The operational reserve and pending BUYs are subtracted. Execution is serialized by the existing single-wallet Executor and database process lock. Stale amounts require fresh approval; there is no silent downsizing.
7. **Duplicate protection:** existing durable signed/nonfailed BUYs, tracked holdings, unique intent keys and same-mint pending work still block re-entry into that mint. Restart discards unsigned CREATED work and reconciles saved signatures without replay.
8. **Multi-position monitoring:** the existing loop visits every eligible OPEN Jupiter position independently. Attention backoff and the normal recent-valuation interval remain. Fresh successful valuations update per-position PnL, high water, observed MFE/MAE and Trading Memory observations. Max-hold positions now receive normal observations before ExitEngine; a failed data observation cannot suppress an otherwise due max-hold exit. Manual emergency exit retains priority.
9. **Position errors:** typed unsigned token faults persist attention on that position, with bounded retry/cooldown, without globally pausing other candidates. Genuine system faults still halt entries.
10. **SELL isolation:** each position has its own try/catch and SELL amount/receipt reconciliation. A failed unsigned SELL leaves its quantity and OPEN state intact while later positions continue. Submitted ambiguity remains TRANSACTION-scoped and is never replayed.
11. **IMAGINE regression:** deterministic tests prove an IMAGINE-like OPEN/NEEDS_ATTENTION position does not block independent approved entries, even among twenty holdings. Real IMAGINE must remain represented by its actual quantity and original BUY evidence; no forced SELL, deletion or fabricated closure is part of migration.
12. **UI:** Positions badge remains an informational count without a denominator. OPEN/attention positions remain in Positions, CLOSED in History. Existing token name, quantity, PnL, issue, protective/backoff state and timestamps remain; observed MFE/MAE are added and absent observations display a dash. Queue 10, Watch 30 and Deferred 20 remain workload bounds.
13. **Files:** `src/config.ts`, `src/risk.ts`, `src/engine.ts`, `src/store.ts`, `src/executor.ts`, `src/domain.ts`, `src/server.ts`, new `src/normal-live.ts` and `src/live.ts`; `config/strategy.json`, `package.json`, `public/app.js`; `tests/core.test.ts`, new `tests/normal-live.test.ts`; new read-only `scripts/normal-live-checkpoint.ts`; README, risk policy and this report. No wallet key or ACK was edited.
14. **Verification:** 100 deterministic tests pass, including 1/5/10/20-position full pipeline entries, a second independent BUY, historical controlled isolation, capital reservation/stale claims, UNKNOWN retention, insufficient-capital WATCH, independent SELL processing, and verified normal startup refusing real halts or balance mismatches. Typecheck, lint and build pass. Isolated browser suite passes with zero browser errors, including SSE, navigation, settings, CSRF and responsive flow cases. Historical safety/stop-loss-disabled/restart tests remain green. Paper/mocked tests are not proof of real transactions.
15. **Runtime:** deployment and independent on-chain/UI checkpoint are recorded below. The read-only evidence command `pnpm exec tsx scripts/normal-live-checkpoint.ts` writes `data/normal-live-verification.json`. It neither signs nor submits. It explicitly distinguishes a running normal scanner from a newly confirmed live BUY.

Can one OPEN position block a different valid new BUY solely because it is OPEN? **NO.**

Can ten OPEN positions block a valid new BUY purely because count = 10? **NO.**

Remaining blockers: candidate/security/risk rejection, execution incompatibility, insufficient spendable capital, duplicate/open same mint, unresolved transaction safety, genuine SYSTEM failure, or an explicit operator entry pause. Insufficient capital is `WAITING_FOR_CAPITAL / INSUFFICIENT_SPENDABLE_BALANCE`, returned to WATCH for fresh future qualification. Position count is not a blocker.

Start/restart the compiled normal runtime with `pnpm live`. After source changes, use `pnpm build` first. This explicit live command enables normal entries only after existing authorization, mainnet/signer, pending recovery, OPEN BUY status and actual token balances are checked; it never clears a SYSTEM/TRANSACTION halt. `pnpm start` continues to honor the saved operator entry switch. Only one runtime may own the database/port at a time.
